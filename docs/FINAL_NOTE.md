# Hearth — concept proven

*Written 2026-09-04, end of day one. Everything below exists, runs, and is in the repo.*

## What it is

A small valley in Unreal Engine 5 where six people have to keep each other alive: bring wood, keep the
fire lit, build the shelter, fetch water and food, sleep when it's dark. They talk to each other out
loud, in six different voices, through the Mac's speakers. One of them, Jonah, thinks and speaks
through a language model running entirely on this laptop. You walk in as a seventh person, gather
alongside them, and when you get close to Jonah you can type to him and he answers in character, out
loud, remembering what you said.

It started this morning from a tweet about hearing AI agents talking in the next room. By tonight the
voices are real, the world is real, and the whole thing runs from one command with no API bill.

## How it's built

Two programs, one wire between them.

**The brain** (`brain/`, Python) is the world. It owns time (one tick = ten world minutes), weather,
the five places and what grows there, every person's hunger, thirst, energy, warmth, and health, their
memories, and every decision. Each person is driven by a *brain* behind one interface:

- *Scripted*: rules. Free. Gathers by role, shares food, goes home at night, says a line now and then.
- *Ollama*: a 7-billion-parameter model (qwen2.5) on the M3 Pro's GPU. Free, offline. Decides via a
  JSON schema so every answer is a legal action; holds a conversation with the visitor.
- *Claude*: same interface against the Anthropic API, with prompt caching, structured output, a cost
  meter, and a `--budget` stop. Not used yet; it's a flag.
- *Mixed*: any subset of people on a model, the rest scripted. This is how it runs today: Jonah on
  Ollama, five on rules.

Speech is a field on each decision, heard by whoever is standing at the same place, throttled so nobody
narrates, and spoken by macOS text-to-speech one line at a time while the world waits. Everything the
models are told lives in plain files in `brain/prompts/`: the baseline `world_rules.md`, each person in
`personas.toml`, the visitor-conversation rules, the memory-reflection prompt, and a hint for the small
local model. Edit, restart.

**Unreal** (`unreal/Hearth/`, C++) is the body. It connects to the brain over a WebSocket and shows
what the brain says is true: spawns a character per person, walks them where the brain sends them at a
speed that matches the sim, shows names, actions, speech, and place labels, marks the AI person with a
tag, a glow, and a green suit. It sends back only what the player does: talk, gather, drop off. It never
decides anything, which is why the world runs headless in a terminal exactly the same way.

The map is generated by a script: ground, sun, sky, fog, a forest, a river, a meadow, a quarry, a camp
with a fire pit and logs, and a wall of trees around the whole valley. About 1,500 placeholder shapes in
eight flat materials. Real assets (Fab characters, Quixel trees) drop in later without touching the
logic.

**Playing:** `./play.sh`. WASD and mouse, Shift runs, Space jumps, Enter talks to a nearby AI person,
Esc opens a menu with Quit, a Lumen on/off switch (frees GPU memory for the model), a Voices switch, and a
1–10 look-sensitivity slider. A north-up minimap top-right shows every place and person. Stand at a
place ten seconds and you're handed its resource; walk into camp and it's dropped in the stockpile.
Type `hump` and your character does something regrettable for six seconds.

## What it cost

Nothing per hour. Ollama runs the model locally. The scripted five are rules. The only paid path is the
Claude brain, which is one flag away and priced in `PLAN.md`.

## What we learned (the expensive lessons, so nobody repeats them)

- **Unreal's Python API:** `unreal.Rotator` takes (roll, pitch, yaw) positionally. The sun pointed at
  the sky for an hour because of this.
- **Unreal ini files** treat `//` as a comment, even inside a URL. Quote the value.
- **Unreal 5.8 JSON keys** are `TSharedString`, not `FString`.
- **Slate delegates from UObjects** need `CreateUObject`; the `(this, &Func)` shorthand assumes shared
  pointers.
- **A single-node animation instance with no clip reports "playing"**, so "start the idle clip if not
  playing" never fires. Check the asset, not the flag.
- **The engine's tutorial mannequin only knows how to walk holding a rifle.** Epic's Manny/Quinn
  mannequins with the unarmed set live in the engine's template resources and must be copied to
  `/Game/Characters/Mannequins` because their internal references say so.
- **macOS delivers one giant mouse delta when the game window first takes focus.** Arm the look guard
  from that moment, not from level start.
- **Console variables set at "game setting" priority are silently ignored** when the project config set
  them. Use console priority.
- **The Unreal launcher binary re-execs the real game and returns immediately.** A script that waits on
  the command it started thinks the game closed. Wait on the real process.
- **The Python interpreter on this Mac is named `Python`**, capital P, so `pkill -f "python ..."`
  matches nothing.
- **The editor writes into tracked config files on its own** (an Android file-server token, this time),
  and Unreal logs are full of hex that trips secret scanners. Logs are ignored, that plugin is disabled,
  and a pre-commit hook greps for token shapes.
- **Small local models latch onto an opener** ("Hey, thanks…"). Prompt rules help; a de-repetition
  filter and a repeat penalty actually fix it. Quietness has to be enforced in the engine, not requested
  in the prompt.

## Where it goes next

In the order I'd do them:

1. Fab characters replacing the mannequins, Quixel trees replacing the cones.
2. Day/night lighting from sim time; a flame when the fire is lit; the shelter appearing as it's built.
3. Voices coming from where each person stands instead of the laptop speaker.
4. One paid Claude session on all six with a small budget, to see what real emergent cooperation looks
   like next to the local model.
5. Memory that survives a restart, so tomorrow they remember today.

The plan with checkboxes is `PLAN.md`. What every part does is `docs/FEATURES.md`.
